# Default — split by subject, not by record type

Split the material by the distinct real-world SUBJECTS it covers — each a thing the user would seek
advice about, with its own body of facts — and give each one specialist.

Never make a specialist for a category of the user's own records: costs, expenses, payments, dates, a
schedule, a list, contacts, documents, photos, a "tracker", a "dashboard", or a whole-material
"overview/summary". Those are app DATA — rows in the project's tables. Combine parts that serve one
continuous purpose; do not split a subject just because it holds several kinds of records.
